# P1 历史复盘与反事实分支

> 更新日期：2026-10-13 · P1.1–P1.3 已实现。历史 JSON 协议仍为 2、SQLite schema 仍为 4、规则 basic-v1 / 版本 1；没有新增依赖或修改规则引擎。

## 玩家入口

普通牌桌与工作台均可打开 **对局历史 → 查看副牌 → 查看详情 → 开始复盘**。

- 起点、上一步、下一步、完整动作时间线、轮次/阶段跳转、播放/暂停。播放间隔 800 ms，到末端自动暂停；跳转或切换路径暂停播放。
- 复盘从校验通过的起点与动作父链读取，入口沿用完整逐动作规则重放校验，不重新请求模型，不恢复或提交活动牌局，不订阅全局思考/音效。
- 每个节点同步当前/上一墩、赢家、庄闲得分、剩余手牌、合同、主牌与结算。跨副 `nextHand` 节点仍可查看，新副后续从副牌列表打开。
- 四座视角与全牌复盘。普通视角隐藏其他暗牌；100 分搭档明牌只在成功扣底后显示，并随节点更新。全牌选项仅影响复盘显示，AI 始终使用阶段合法观察。
- 按观察位置展示已保存评估：首点、动作前、节点后分别关联；候选、建议、实际执行动作、采用/未采用/失效、实际配置、模型、耗时与回退分开呈现。缺失记录写“未采集”，结算节点展示公开结果，不伪造决策观察。

## 分支与继续模拟

在合法节点点击 **新建分支**，可以更改叫分、主牌、扣底或合法出牌，也可以选择已有四类引擎的当前默认配置，**模拟一步**或**继续模拟本副**。新分支在首个合法动作确认保存后出现在路径列表；原后续不裁剪，支持同一起点的多个 child 和嵌套分支。

- 独立 `HistoryBranch` 保存来源节点、父链、配置快照和座位绑定。动作与评估在既有 HTTP 事务内写入；分支结算不更新真实副摘要或比赛状态。
- 每个模拟动作经规则校验，并记录合法观察、候选、实际建议、耗时和回退；每一步等待存档确认。每次连续模拟最多 512 个动作，在副/整场结算、取消或错误时停止。
- 模拟使用独立引擎管理器、决策日志和思考服务，不使用活动局的全局日志/思考槽。切换节点、路径、配置或关闭复盘会取消请求，忽略取消信号的迟到结果也不能提交。事务写入期间锁定节点切换；已经提交的动作保留。
- 写失败/确认丢失时游标不推进，保留同一个包供幂等重试，也可导出待保存分支。保存成功后重新读服务端详情，获取实际生效配置版本；读取失败或返回过期详情显示“已保存，但详情同步失败”，重试仅同步读取，不重复写动作。
- “原局与分支比较”展示各路径来源、后续动作与真实结束结果。单个分支不作为统计牌力证据。

## 验收证据与边界

测试先行：复盘交互测试先因缺少“开始复盘”失败；分支操作先因缺少“新建分支”及未实现提交/模拟失败；实际配置同步先复现客户端版本代替服务端版本；过期详情先复现保存后错误接受旧游标。各目标失败后实现对应行为并通过相关回归。

`tests/history-replay*.test.ts`、`tests/history-branch.test.ts` 覆盖四阶段逐节点状态/观察、跟牌、提前结束、整场结算、跨副、分数守恒、100 分明牌、已采用与未采用评估、多个 child/嵌套分支、非法动作、丢失确认重试、实际配置同步、过期详情拒绝及迟到结果隔离。`tests/history-p1-acceptance.test.ts` 为验收标准独立抽查：切换全牌/座位视角与新建分支后原副数据不被改写，从中间节点换动作时原后续节点全部保留且原路径仍可回放到原尾部，100 分明牌仅在扣底完成后公开（叫分、定主阶段及未叫满 100 时不公开），跳转/播放复盘不实例化远端决策引擎或发起网络请求。真实浏览器使用临时 SQLite 库验证历史入口、牌桌布局、分支写入和原路径比较。

当前分支选择是四类引擎的当前默认配置，不声称恢复旧服务端点或支持同类型多配置/四座独立路由（P2）。批跑、换边统计、独立模拟比赛与报告仍属于 P3。分支未确认包目前保留在复盘会话内；关闭/刷新前应重试成功或导出，不自动合并到活动局的待保存日志。纯离线 Tauri 原生 SQLite 和历史文件导入仍未实现。

交付检查：`pnpm test`、`pnpm build`；最终数量以当次实跑为准。未修改 `src-tauri/`。
