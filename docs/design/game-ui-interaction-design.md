# UI 与游戏交互设计

本文维护体验目标与交互取舍。正式约束以[交互规范](../ui/interaction-guidelines.md)为准，当前入口见[玩家指南](../guides/playing.md)，后续状态见[开发路线](../planning/development-roadmap.md)。

## 体验目标

- 玩家随时能判断谁行动、主牌和合同是什么、双方还差多少分，以及自己可以做什么。
- 普通对局优先呈现牌桌与行动，技术诊断通过设置中的开发者选项进入。
- 用稳定布局、清晰牌面和明确反馈减少误点；音效、报牌与动画节奏均可控制。
- 单副练习与短教学独立于标准对局，退出后原会话保持暂停，迟到请求不能污染原局。

## 信息与布局

牌桌保留四方座位与正方形边界；身份、行动者、主牌、合同、吃分和目标线常驻。普通、Debug 与观战共用牌面和座位朝向，显示权限按模式控制。

桌面用侧栏组织当前行动、战况和记录，窄横屏保持主要操作与手牌可达。触屏四家手牌可独立滚动，拖动只滚动、不误选；不能靠缩小字号或牌面解决空间问题。

设置、规则、看牌、理由、历史和结算使用统一侧栏停靠外框。打开时暂停并隔离背景输入，关闭后保持暂停；四家牌面与常驻信息仍可查看。尺寸、热区、焦点和遮挡要求统一见[交互规范](../ui/interaction-guidelines.md)。

## 阶段交互

| 阶段 | 必须说明与反馈 |
| --- | --- |
| 叫分 | 当前最高叫分、合法档位、放弃及当前行动者 |
| 定主 | 庄家、叫分与可选花色；选择后由规则提交 |
| 拿底/扣底 | 拿底揭晓、四张非分牌选择、剩余数量与非法操作反馈 |
| 出牌 | 当前墩、领出花色、合法跟门、选中牌和确认方式 |
| 结算 | 实际赢家、合同与吃分、本副复盘及继续入口 |

选牌与确认分开；点牌即出由明确偏好控制。多牌扣底达到数量上限时反馈原因，智能建议不代替玩家确认。不能仅用颜色区分选中、禁用与可跟牌。

100 分局只有成功扣底后才公开庄家搭档剩余手牌，后续随出牌同步。Debug/全牌复盘的显示不能扩大普通 AI 输入。

## 模式与失败反馈

- 观战沿用当前会话，可暂停、单步和退出；人工残留选择不阻止 AI 推进。
- 原动作复盘读取保存动作，切换节点不调用模型；反事实变化进入独立分支。
- 历史保存失败明确显示待保存状态，重试沿用身份，不自动继续运行。
- 模型等待、取消、实际回退与无动作错误分开反馈；引擎名称与真实执行配置一致。
- 认分牌、跟门/缺门短教学使用固定公开题目，不读取活动暗牌、调用模型或生成多余历史。

## 实现与验证

组合入口在 `apps/web/src/App.tsx` 与 `hooks/useGame.ts`；牌桌、手牌、侧栏和弹窗位于 `components/`，视觉变量位于 `styles/`。规则、会话和 AI 分属独立共享包，具体边界见 [Monorepo 说明](../architecture/monorepo.md)。

[可点击原型](../ui/interaction-prototype.html)用于独立演示，并由 `tests/ui-design-prototype.test.ts` 保留结构回归；原型不连接真实 AI、存储或完整产品入口。正式应用以单元与真实浏览器用例验证，不保留每轮截图和评审流水。

```bash
pnpm test
pnpm test:browser
pnpm build
```

新增交互遵循 TDD。浏览器验证检查实际矩形、牌桌比例、花色/角标、真实触屏命中和弹窗遮挡，不能只检查按钮边框或凭构建通过判断。

## 桥牌成熟产品参考

RealBridge 的行动者提示和确认方式、Funbridge 的玩家视角与目标进度、BBO 的误点反馈与撤销边界可用于交互研究。参考交互习惯时仍保持幺子分独立的规则、信息公开时机与计分，不照搬牌型规则或未经验证的收益结论。
