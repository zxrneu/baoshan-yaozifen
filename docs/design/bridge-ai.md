## 1. 游戏规则与桥牌经典博弈论对应分析

保山幺子分与桥牌都包含契约、搭档与跟牌约束，可以借鉴桥牌搜索和战术。这里是算法类比，不据此认定游戏起源或规则从属关系；各自的牌张、吃分目标和信息结构仍有差异。

### 1.1 规则同构与差异映射

| 游戏机制维度 | 契约桥牌 (Contract Bridge) | 保山幺子分 (Baoshan Yaozifen) | 算法映射与策略推导 |
|---|---|---|---|
| **基本博弈骨架** | 4人，固定两两搭档 (东西 vs 南北) | 4人，固定两两搭档 (东西 vs 南北) | 2v2 零和博弈；收益严格绑定；座位顺时针/逆时针出牌次序完全同构 |
| **手牌与规模** | 52 张牌，4 门花色，每人 13 张，无底牌 | 52 张牌，4 门花色，每人 12 张，留 4 张底牌 | 牌空间规模相近（12 轮 vs 13 轮）；庄家拿底扣底（非分牌扣底）增加了底牌先验与庄家手牌塑造阶段 |
| **主牌与明牌机制** | 阶梯叫牌定约，最高叫品定庄与定主；首张领出后搭档明手全公开 | 分数叫牌（70~100分），庄家自主定主；**叫到 100 分扣底后庄家搭档明牌全公开** | 庄家定主后主牌地位与桥牌将牌完全一致；100分定约触发明手机制（Dummy Hand），转化为部分完全信息博弈 |
| **出牌与比较** | 首家领出；有领出花色必须跟同门；缺门可将吃或垫牌；大牌压小牌，主牌压副牌 | 规则完全一致（跟门、缺门杀牌/垫牌、主牌压副牌） | **吃墩比较与领出权归属逻辑完全同构**；桥牌的所有出牌合法性状态机可直接复用 |
| **核心区别：目标函数** | **按墩数计分 (Trick Count)**：每赢一墩都计入定约墩数；单张牌无点数差别（K赢墩和2赢墩价值相同） | **按分牌计分 (Point-Taking)**：全副仅 A(10分)、10(10分)、5(5分) 计分，合计 100 分；K/Q/J/2~9 均为 0 分 | **策略核心差异**：空墩（0分墩）只涉及领出权和牌力消耗；高分墩（可达25分）关乎胜负命脉。0分大牌（K/Q/J）是绝佳的控制牌与保护牌，分牌（A/10）是抢分利器也是易被杀的负债 |
| **获胜判定** | 达到定约墩数成局，超墩有额外奖分 | 二元硬性阈值：庄家吃分 $\ge B$ 成局，闲家吃分 $\ge 105 - B$ 击垮定约；超额吃分不增加胜副 | 属于**定约达成型极小化极大博弈**；达到目标线 $\beta$ 剪枝立即可行，无需追求多余无用分 |

## 2. 桥牌出牌获胜核心算法借鉴

在世界计算机桥牌锦标赛中，顶尖无模型算法（如 GIB、Jack、Wbridge5 等）的核心支柱包含：

### 2.1 双明手求解器 (Double Dummy Solver, DDS)
- **概念**：在全明牌（4家手牌已知）假设下，使用带 **Alpha-Beta 剪枝的极小化极大 (Minimax) 搜索**。
- **位棋盘加速 (Bitboard)**：使用 64 位无符号位掩码表示手牌与花色，合法性校验与比大小进入纳秒级。
- **等价牌压缩 (Rank Equivalence Class)**：同门连续且无未出牌间隔的 0 分牌（如场上无更大牌时手持 ♥9 与 ♥8），在吃墩与得分上完全等价，合并为一个分支进行搜索，剪枝率达 70%~90%。
- **目标截断 (Target Pruning)**：搜索一旦满足成局分数线，直接触发硬截断返回胜局。

### 2.2 分割/完美信息蒙特卡洛 (PIMC, Partitioned / Perfect Information Monte Carlo)
- **概念**：针对暗牌不完全信息博弈，利用贝叶斯先验与动态规划均匀采样 $N$ 个符合历史缺门与已知牌约束的可能世界 (Worlds)。
- **深度评估**：对每个候选出牌动作 $a$，在各个世界中不再采用傻瓜式随机乱出 (Rollout)，而是直接调用 **DDS 极小化极大搜索或前瞻博弈树**，评估双方理性对抗下的真实胜负。
- **统计合并**：通过配对统计与置信区间，选出在全部可能世界中期望赢副率最高的合法牌。

### 2.3 桥牌专家出牌战术体系 (Bridge Heuristics)
- **做庄规划 (Declarer Play)**：
  - **拔主/清主 (Drawing Trumps)**：己方主牌占优且副牌有坚固赢张（A、10）时，首要任务是拔清防守方的主牌，消除被将吃的风险。
  - **兑现赢张 (Cashing Established Winners)**：在敌人形成缺门将吃之前及时兑现副牌大牌。
  - **树立长套 (Suit Promotion)**：利用长套副牌逼出对手大牌，将后续小牌树立为赢张。
  - **安全脱手 (Throwing the Lead / Exit)**：在不利于领出时，用无用牌安全让权给对手或搭档。
- **防守战术 (Defender Tactics)**：
  - **第二手出小 (Second Hand Low)**：第四手是敌人且情况不明时保留大牌，避免过早暴露。
  - **第三手出大与喂分 (Third Hand High & Feeding Points)**：搭档领出小牌时出大牌争墩；搭档所出牌已稳赢时，**安全喂出分牌 (10或5)**。
  - **第四手便宜拿 (Fourth Hand Cheap Win)**：最后一家明确知道归属，敌方大则用最小可压牌赢下；己方稳赢则垫最大分牌或无用小牌。

## 3. 分层无模型深度思考架构

系统采用分层流水线（Tier 0 ~ Tier 3），在保证 0ms~250ms 延迟可控的前提下最大化胜率：

┌────────────────────────────────────────────────────────────────────────┐
│                        PlayerObservation (合法观察输入)                │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│  Tier 0: 零延迟硬战术预处理 (Tactical Pre-Filter, < 0.1ms)             │
│  - 唯一合法牌直接出牌 (Single Legal Move)                              │
│  - 胜负已锁定安全脱手 (Locked Match Discard)                           │
│  - 搭档稳赢保护与无收益牌精简 (pruneCandidates / 消除高牌消耗)         │
│  - 等价牌等价类合并 (Rank Equivalence Compression, 如KQJ同门0分连续牌) │
└──────────────────────────────────┬─────────────────────────────────────┘
                                   │ 剩余候选牌 >= 2
                                   ▼
┌────────────────────────────────────────────────────────────────────────┐
│  Tier 1: 桥牌专家战术规则器 (Bridge Heuristics Engine, ~1ms)           │
│  - 轮内位置特异性决策：领出(拔主/兑现/长套)、第二手出小、第三手喂分、第四手便宜拿 │

                                   │ 若时间预算充足 (>= 20ms) 且中后盘

│  Tier 2: 完美信息双明手求解器 (Bitboard DDS Solver, 纳秒级极小化极大)   │

## 4. 关键算法模块详细设计

### 4.1 位棋盘快速状态表达 (`bitboard.ts`)

为了在 200ms 预算内推演数百个世界的双明手博弈树，手牌与吃墩状态必须避开对象分配，全部用整数位掩码表达：
- **花色编号**：`S=0, H=1, D=2, C=3`；
- **点数位图**：从 `2`（bit 0）到 `A`（bit 12），共 13 位；
- **单玩家手牌**：`Uint16Array(4)`，每个花色一个 16 位整数；
- **全场手牌**：`Uint16Array(16)`（4 个玩家 $\times$ 4 门花色）；
- **吃墩比大小**：
  - 同花色大小：比较位图最高有效位 `clz32(mask)`；
  - 主牌判断：主牌花色位图直接胜过非主牌；
- **分牌查找与分值计算**：预计算 8192 大小的查找表（LUT），位图直接查得该手牌中的分值。

### 4.2 桥牌战术专家体系 (`heuristics.ts`)

针对领出、第二手、第三手、第四手设计专门的战术函数：
1. **`evaluateLead(observation, legal)`**：
   - 己方主牌优势指数：$\text{Adv}_{trump} = \text{MyTrumps} + \text{PartnerKnownTrumps} - \text{EstOpponentTrumps}$；
   - 若 $\text{Adv}_{trump} \ge 2$ 且副牌有坚强 A/10 赢张：优先清主；
   - 若持有副牌坚强赢张（A 或未见牌中最大的牌）且后手无绝门杀牌威胁：优先兑现；
   - 否则：选择安全套或长套脱手引牌。
2. **`evaluateSecondHand(observation, legal)`**：
   - 默认执行“第二手出小 (Second Hand Low)”；
   - 除非持有紧密连张（如 KQ 出 Q 试探），否则跟出同门最小牌。
3. **`evaluateThirdHand(observation, legal)`**：
   - 若搭档第一手领出已稳赢：**安全喂分 (Feed Points)**，跟出 10 或 5；
   - 若搭档牌小，存在被第四手反超危险：**第三手出大 (Third Hand High)** 争夺领出权。
4. **`evaluateFourthHand(observation, legal)`**：
   - 处于完全信息轮内结算；
   - 搭档已赢：喂最大分牌或丢最小牌；
   - 对手当前赢：若能压过，评估吃分价值是否跨过成局线；以最小压过牌赢下。

### 4.3 双明手 Alpha-Beta 引擎 (`dds.ts`)

在采样世界中求解双方最优应对：
- **博弈树定义**：
  - 庄家方（东西或南北，取极大化）；
  - 闲家方（取极小化）；
- **状态转移**：四家出一张牌算一轮，轮末赢家获得分数并成为下一轮领出者；
- **Alpha-Beta 边界**：
  - $\alpha$：庄家方保证的最少得分；
  - $\beta$：闲家方允许庄家获得的最大得分；
- **胜负锁定硬截断**：
  - 庄家方累计得分 $\ge B$：直接截断并返回 100（庄胜）；
  - 闲家方累计得分 $\ge 105 - B$：直接截断并返回 0（闲胜）；
- **置换表 (Transposition Table)**：
  - 使用 Zobrist 散列或全场 16 门手牌位图组合作为缓存键，避免重复搜索相同手牌集合。

### 4.4 深度思考模式时间预算与参数配置

在默认“深度思考”配置下：
- **总时限**：`timeLimitMs: 220ms`（预留 30ms 浏览器渲染与调度缓冲区）；
- **最小样本世界数**：`minWorlds: 16`；
- **最大样本世界数**：`maxWorlds: 64`；
- **残局完全求解触发**：剩余手牌 $\le 6$ 张时，自动激活 DDS 全局精确求解；
- **前中盘**：DDS 2~3 轮前瞻 + 桥牌战术叶子节点启发式评估；
- **优雅降级**：超出预算时平滑返回上一个完整检查点的胜率推荐，或使用 Tier 1 桥牌专家规则即时兜底。

## 5. 接口与 SOLID 设计遵循

1. **单一职责原则 (SRP)**：
   - `bitboard.ts` 专注位运算状态转换与纳秒级吃墩判定；
   - `heuristics.ts` 专注桥牌专家战术评估；
   - `dds.ts` 专注完美信息 Minimax / Alpha-Beta 求解；
   - `pimc.ts` 专注多世界约束抽样与统计聚合；
   - `bridgeEngine.ts` 专注统一封装 `DecisionEngine` 异步契约与日志采集。
2. **开闭原则 (OCP)**：
   - `BridgeEngine` 实现了 `DecisionEngine` 接口；
   - 作为默认算法引擎插入 `DecisionEngineManager`，完全不破坏 `useGame` 与界面组件。
3. **里氏替换原则 (LSP)**：
   - 任何合法牌输入下保证输出合法牌；在单元测试、模拟器与真实牌桌上可完全替代原有算法。
4. **依赖倒置原则 (DIP)**：
   - 高层牌桌组件依赖 `DecisionEngine` 抽象，不硬编码具体求解器细节。
