# Laya / System One 演进候选

> 文档类型：候选设计；源码复核日期：2026-10-14。当前引擎与路由见[决策架构](../architecture/decision-engines.md)。返回[文档索引](../README.md)。

## 当前能力与设计起点

[LayaEngine](../../packages/ai-core/src/engines/layaEngine.ts)适配 TypeSafe / Ollaya 的 `/v1/systemone` 选择题协议。叫分、定主、出牌可调用模型；扣底明确使用 `buryFromObservation` 启发式。唯一出牌候选直接返回，不计模型调用。端点、模型与预算由配置决定，没有足够证据为目标设备承诺固定模型延迟或牌力。

出牌请求已经提供本家手牌、公开搭档牌、主牌、合同、庄闲得分、当前墩、已完成墩数与公开缺门；并未提供完整已结束出牌历史。当前 instructions 是简短阶段指令。可基于这些差异提出输入与规则指引实验，但不能把模型缺少某种输入直接等同于已证实的决策缺陷。

引擎与 RPC 已使用阶段观察和白名单，规则明牌在成功扣底后才公开。候选改动继续复用[已有隔离边界](../architecture/information-isolation.md)，原方案中“需要从零建立物理隔离”的说法不再作为当前待办。

## 候选改动与验收

| 候选 | 实验问题 | 验收证据 |
| --- | --- | --- |
| 规则与阶段指引 | 更完整的硬规则、获胜线与条件战术是否减少失误 | 规则与策略分开；相同模型/预算下只改变指引，报告改善、退化和实际请求量 |
| 公开历史与看板 | 逐墩出牌、赢家/得分与公开缺门是否帮助判断剩余控制 | 只从合法观察生成；100 分公开手牌同步；跨座位隐藏信息变化不改变输入 |
| 扣底模型化 | 在合法零分牌候选上，模型是否优于当前启发式 | 候选合法、张数与归属校验，模型原生来源独立归因；固定其他阶段做消融 |
| 概率与动作选择 | 服务返回的候选打分是否可用于可靠选择 | 先核实服务协议及响应形状；非法、缺失、非有限值和失败路径显式测试 |

候选概率即使只在合法集内比较，也不等于校准后的赢副率；不把重归一化当作“永不失败”的保证。未知模型能力和未支持响应字段先做协议探针，不写成已经可用的实现。

## 推进边界

按一个明确变量开展：先固定当前配置与请求/响应记录，再验证相关场景和信息隔离；小规模服务冒烟后按预声明预算做重复对照，最后用独立换边整副牌确认。依据[研究规格](../planning/ai-research.md)选择下一项，任务状态不在本文重复维护。

扣底模型化、新 Prompt 或更大输入不自动进入产品默认。已有多配置与备用路由见[P2](../features/engine-profiles.md)，独立模拟和实际请求统计见[P3](../features/simulations.md)；牌力结论及默认替换遵守[统一评测](../ai/evaluation-plan.md)。原方案的预算、参数和伪代码只作历史参考。
