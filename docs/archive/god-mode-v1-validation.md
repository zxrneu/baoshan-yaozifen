## 1. 本次交付

首版覆盖设计步骤 1～3，并接入已有 LLM 能力：

- UI 与验证脚本共用 `GameSession`。暂停、预计算、建议、单步与自动动作使用统一评估和提交入口；撤销、重开、手动接管、导入或换参数使旧请求立即失效。
- 当前行动座位可人工叫分、定主、扣底或出牌。建议只评估，采用建议才推进；四座 AI 连打包括南家。每个成功动作进入可撤销、恢复的线性历史。
- 区分 AI 评估和实际提交。日志覆盖四阶段，保存实际引擎、模型、动作、请求上下文、原始响应与回退原因；人工操作有独立来源记录。
- 版本化完整 JSON 快照可导入、导出、继续执行和回放；恢复规则函数，校验 52 张牌的归属、跟门、叫分、墩结果、得分与回放最终状态。非法导入保持当前局面。
- LLM 模型、协议、响应格式、推理等级和预算同步到每次服务端请求；阶段 JSON Schema 约束动作字段与合法候选，规则引擎做最终校验。
- 唯一候选和开发模拟明确归于本地执行；回退不冒充模型成功。未返回的模型置信度显示不可用。
- 牌桌适配桌面与笔记本视口，窄宽度采用上下布局与滚动；输入框和原生按钮保留键盘行为。

首版使用一个统一引擎，尚未实现逐座位 profile、同节点多引擎比较、保留多分支的历史树、场景编辑器或 Oracle。快照保存状态、动作路径和引擎类型；连接参数、模型与推理配置使用本机设置，不能把快照当成完整实验配置包。历史最多保留 1000 个节点，超过后以保留的检查点作为回放起点。

## 3. 真实模型整局结果

配置：`qwen38_27b`，Chat Completions，`reasoning_effort=none`，`response_format=json_schema`，单请求预算 60000 ms。使用本项目既有服务端连接，只发送固定 seed 42 生成的测试牌局观察；目标胜副数设为 1。

执行从发牌开始，无人工叫分或阶段跳过，经叫分、定主、扣底、出牌到 `matchEnd`：

| 指标 | 结果 |
|---|---|
| 总耗时 | 212722 ms，约 3 分 33 秒 |
| 实际提交 | 46 个动作 |
| 有效真实模型响应 | 41 次 |
| 唯一候选直接执行 | 5 次，未调用模型 |
| 模型失败 / 算法回退 | 本样本 0 次 |
| 模型调用耗时中位数 | 3597 ms |
| 模型调用 P95 | 12304 ms，41 个样本的 nearest-rank 分位数 |
| 模型调用耗时范围 | 1574～21185 ms |
| 最终状态回放 | 通过；保存的 46 个动作重放后与导出的终局状态一致 |

阶段明细：

| 阶段 | 提交动作 | 模型成功 | 唯一候选直接执行 |
|---|---:|---:|---:|

## 4. 联调中发现并处理的问题

1. **前端设置没有完整到达服务端**：请求现已携带模型、协议、响应格式、推理等级与预算；每次请求创建独立 LLM 实例，运行中的实例不会被新设置修改。服务端仅接收这些已知参数，连接地址和鉴权保持由服务端环境控制。
2. **none 选项实际被丢弃**：原客户端将 `none` 与默认配置一起省略。现 SDK 和 Fetch 都会传递显式 `reasoning_effort`；兼容服务的新 `reasoning` 字段和旧 `reasoning_content` 字段均可读取。参数是否支持仍取决于模型及部署，参见 [OpenAI Chat Completions 参数](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create) 和 [vLLM 推理输出说明](https://docs.vllm.ai/en/stable/features/reasoning_outputs/)。
3. **扣底超时或回显输入**：初始 `default + json_object` 联调出现 120 秒扣底超时；`low + json_object` 探针返回输入局面，没有 `cards`。严格解析拒绝该响应并记录回退。补充扣底专用指令及阶段 Schema 后，`none + json_schema` 的独立扣底探针 5668 ms 成功，随后完整对局也成功。多个因素同时变化，不能将改善单独归因于某个参数。
4. **失败与模拟被当作模型成功**：日志现记录实际执行引擎；开发模拟、唯一候选和回退单独标识，用户取消不会再触发降级动作或残留日志。
5. **伪造的默认置信度**：原解析器缺字段时填入 0.9，现保持缺失。即使模型提供置信度，也只是自报值，未做校准。
6. **断开连接后继续推理**：服务端监听请求取消与响应连接关闭，传递 AbortSignal，清理监听器；取消结果不得提交。

初始探索跑因总预算 12 分钟停止，另有本地执行沙箱限制导致的连接失败样本。它们用于诊断和回退验证，均未合并到上述成功整局的耗时与失败率统计。

## 5. 本地复现

前端一体化开发（现有服务端环境需配置可用模型）：

~~~sh
pnpm install
pnpm dev --host 127.0.0.1 --port 5173
~~~

进入上帝调试 → 引擎参数设置 → 选择 LLM、Chat、JSON Schema、none、60000 ms → 保存并应用。选择固定 seed 或导入完整快照；用「当前动作建议」观察，用「立即执行」（采纳建议）或「AI 代走一步」提交，用「四座 AI 连打」自动运行。none 和 JSON Schema 是本次验证有效的组合，其他部署需单独确认能力。

为了让实机测试不受开发热更新重启影响，可另开稳定的决策服务：

~~~sh
HOST=127.0.0.1 PORT=3012 pnpm run server
~~~

在另一终端执行：

~~~sh
pnpm exec vite-node scripts/evaluate-god-llm.ts -- \
  --url http://127.0.0.1:3012/api/decision \
  --seed 42 --reasoning none --format json_schema --timeout 60000 \
  --output /tmp/god-llm-v1-full.json
~~~

脚本将记录每步实际引擎、耗时和回退，并输出完整快照及日志；有运行错误、未完成整局或没有真实模型成功响应时返回非零退出码。单阶段探针可加 `--probe-phase bury`，恢复已有快照或评估输出可加 `--resume <文件>`。实际重新推理可能产生不同动作；确定性回放请使用已保存的动作序列。

## 6. 下一步先后顺序

1. 扩大 LLM 协议回归：增加不同 seed 的四阶段样本，分别测响应格式和推理预算，统计合法率、回退率、取消响应与延迟；把回显等坏响应纳入固定夹具。
2. 按架构步骤 4 实现逐座位 profile 与完整有效配置记录，使同类模型不同参数能在同一副隔离运行。
3. 按步骤 5 实现同节点多引擎比较与参数重测，保留所有合法候选和每个结果的来源、耗时及上下文。
4. 按步骤 6 做无界面配对评测、阵营交换和多 seed 统计，届时再评估算法强弱；之后推进历史分支、场景编辑与 Oracle。
