# 幺子分 AI 评测

目的是区分动作合法、战术表现、实战牌力和服务可靠性。先明确用户本轮要回答的问题，再选择最小足够的证据；不把评测请求扩展成训练、调参或默认替换。

## 从现有入口开始

以当前工作区根目录为准，先读 `AGENTS.md`，再按任务阅读：

- [统一评测方案](../../../docs/ai/evaluation-plan.md)：数据契约、归因、命令与结论边界。
- [当前路线图](../../../docs/planning/development-roadmap.md)：未完成项、独立确认与默认替换门槛。
- [评测结果](../../../docs/ai/evaluation-results.md)：已有成绩与历史版本限制。
- [P3 模拟契约](../../../docs/features/simulations.md)：配置冻结、取消续跑、报告和复盘。

以代码、manifest 和当次实跑为事实来源；不从规划勾选推断当前通过，也不重建已有评测器。

| 任务 | 优先复用 |
| --- | --- |
| 规则、投影、采样缺陷 | `tests/engine-fairness-isolation.test.ts`、规则与对应模块回归 |
| 单步战术或提示词诊断 | `scripts/evaluate-engines.ts`、`src/ai/eval/` |
| 数据覆盖审计 | `scripts/evaluate-scenario-coverage.ts`、`data/evaluation/` |
| 整副牌对照 | P3 HTTP 模拟与配置版本；或核对能力后使用 `scripts/match-battle.ts` |
| 排队、重试、取消、请求归因 | `tests/llm-lifecycle-evaluator.test.ts`、`tests/llm-streaming.test.ts`、`tests/simulation-service.test.ts` |

## 执行前界定实验

写清一个假设和有意变化的变量，并固定对手、阶段组合、样本、提示词、格式、配置与资源预算。找出产品的实际默认配置；不要把 CLI 的 `bridge-deep` 当作产品默认。

- 区分公开开发场景、验证集与未参与调参的确认集。按整副牌划分、核对互斥；缺保留集时说明无法确认泛化，不用开发集冒充。
- 模型别名不等于真实权重版本。记录可取得的模型、量化、服务、规则、源码、数据与配置指纹；缺 usage、服务分段耗时等字段时写“未采集”。
- 真模型实验先估算请求量与总预算。用户未授权服务调用或预算不明时，先完成离线检查和实验设计；不自动运行所有模型。
- 缺陷与行为改动遵循仓库 TDD；新增纯评测覆盖可先验证现有行为，不人为制造产品故障。

## 信息隔离是前置条件

普通引擎、RPC 和 Actor 只接收对应阶段观察。检查并回归：其他座位暗牌、未知底牌与发牌 seed 不进入输入；100 分搭档明牌仅在成功扣底后公开，并随出牌同步。完整状态可供存档或离线裁判使用，但不能回灌决策。God-mode 结果单列。

守恒与计分沿用引擎：分牌不可扣底；闲家锁定线为 `105 - B`；已吃分、未打出分与底牌分之和为 100。不要为让战术样本通过而修改规则。

## 运行与保留证据

在工作区根目录可使用下列已存在的离线入口；运行前核对当前脚本参数与输出位置：

```bash
pnpm exec vitest run tests/engine-fairness-isolation.test.ts tests/eval-integrity.test.ts
pnpm eval:coverage
pnpm eval:engines --engine bridge-fast --concurrency 1
```

覆盖审计只打印报告；`eval:engines` 会写评测产物。先识别已有文件与引用，保留脚本生成的独立 run、manifest、报告和原始轨迹；不要覆盖或删除用户成果。没有 `--repeat` 的入口通过独立运行实现重复，不虚构 CLI 参数。按实验需要扩展到其他配置，失败与回退仍纳入报告。

核对归因：

- 唯一候选、搜索/启发式、Mock、模型原生结果、实际回退与无动作执行失败分别统计。
- HTTP 尝试与 SDK 重试来自真实传输点；流式分块不算新请求；未采集计数用 null，不能填 0。
- 原生合法/成功与含回退系统成绩分开；失败组不静默丢弃，干预/排除必须报告。
- 小残局 DDS 用于校准给定世界的搜索，不证明普通视角整局最优。

整副牌用同种子换边、实际 `winnerSide` 和发牌组作为统计单位；同组两局不当作独立样本。固定阶段比较与全生命周期成绩分栏，吃分只作辅助。重复调参后用独立确认批次，区间跨 0 时写“尚无可靠优势”。

## 输出与放行

交付说明包含问题、基线/候选、数据与配置版本、运行命令、有效组数、质量/延迟/请求量、故障/回退和原始产物位置。区分本次测量与历史引用，缺证据的结论明确保留。

默认替换按当前路线图：规则与隔离通过；独立确认集上实际赢副率差的 95% 区间下界大于 0；合法性、完成/回退表现达标；目标环境端到端 P95 不超过预声明预算。仅提速或离线替换另用等效/非劣协议，不宣称牌力提升。

工程改动交付前执行 `pnpm test`、`pnpm build`；原生改动另跑仓库要求的 Cargo 检查。报告审阅本身不要求重跑收费实验，也不授权修改默认引擎。
