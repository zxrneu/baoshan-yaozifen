## 0. 本轮调整与历史修正

本轮明确优先建设可以保存、复盘和对战模拟的基础工具。SQLite 是历史存储；引擎创作是现有四类引擎的多个独立参数/模型配置，LLM 与 System One 支持文件中定义多条可选服务，通过 HTTP 决策。AI 牌力实验与 RL 保留，但不阻塞这条主线。

v1/v2 中有价值的事实复核继续保留：已完成能力不重复立项，已推翻故障不再执行原修法，任务按依赖和验收关闭，不承诺固定日历工期。

| 旧版问题 | 新版处理 |
| --- | --- |
| 下一项固定为 T1.3 小屏适配，评测建设排在后面 | 先交付历史存库、复盘与配置模拟，评测修复配合模拟验收 |
| E2/E4 仍要求从零建设对战、日志与阶段统计 | 标记已有基础，补请求级归因、重复运行、独立验证和 LLM 对战 |
| 保留“每次跟牌 DDS 空转”等已推翻判断 | 当前计划只保留复核结论；原问题描述归档 |
| PIMC 偶发失败仍被列为当前故障 | `e41803b` 已修预算降级并用确定性时钟注入守护；不把复现测试误判为新缺陷 |
| “没有对局数据”“UI 测试为零”已过时 | 现有导出、完整评测轨迹和 App 点击测试进入现状盘点；训练语料治理另立任务 |
| 测试数及小时/周次估算过时 | 验证以当次实跑为准；任务以依赖和验收关闭，历史报告保留当时数字 |

会话提交已接入 SQLite 自动存档、跨重启历史列表、校验导出与未结束副牌恢复；撤销接管在数据库中保留旧路径，内存回放仍为有界窗口。历史保存默认配置的不可变版本与实际回退配置，配置参数/服务端点的恢复和四座独立 profile 路由按 P2 补齐；P1 原动作逐步复盘、节点诊断和独立反事实分支已完成，见 [P1 实现说明](p1-history-replay.md)。

Bridge 与 Algorithm 的前三阶段共用 `smart.ts`；Laya 扣底也用启发式。比较时须说明组合策略来源，相同成绩不能当作多个模型独立验证。技术栈和检查项以 `package.json`、`tsconfig.json`、CI 为准，不在规划中维护第二份版本清单。

| 证据 | 可用结论 | 不能推出的结论 |

| 本次规划前已有的 low 档运行（套件 1.2.0，800000 ms 超时、并发 2，19/35 通过、24/35 最终合法，17 条标记回退，P95 1195040 ms（约 19.9 分钟）） | 服务长尾与执行失败严重影响实验，需核对预算和归因 | 11 次无动作失败就是 11 次模型非法出牌；与 none 专项构成受控比较 |

最后一行来自仅用于诊断、未随仓库保留的运行产物（该 run 已按「不保留无关评测产物」删除）。原始日志显示，出牌阶段为 **6 次超时、5 次连接错误、1 次合法但未达战术期望**（`play-safe-exit` 出 `10D`）；没有动作的 11 次异常被当前执行器计为 `isLegal=false` 和 `fallback`，却不代表实际执行了回退动作。

该 run 的 manifest 已记录生效预算；不能仅凭默认 60000 ms 认定配置矛盾，也不能推断它由哪个 CLI 参数启动。调用耗时超过配置预算的原因待复现；当前 `dispatchLlmRequest` 在取得并发槽之后才开始计时，需核对排队、重试、取消和服务链路，不直接把长尾归因于模型。

根目录报告会被后续运行更新；历史结论引用固定 run。套件、源码或配置不同的成绩不拼成当前排行榜；当前套件升级后须重新建立同版基线。

## 2. 当前主线与首批交付

玩家闭环是：**打一副牌 → 自动保存到 SQLite → 从历史逐步复盘 → 选择不同配置重新模拟 → 查看结果并打开具体副牌复盘**。首批先交付 P0 + P1 的原路径回放，随后扩展配置与模拟；无需等待模型强度排名或 RL。

| 阶段 | 目标 | 依赖与状态 | 退出条件 |
| --- | --- | --- | --- |
| **P0 · SQLite 对局历史** | 保存普通对局、接管、动作与诊断；历史列表及恢复 | 已完成；复用提交/快照边界，协议 2 / schema 4 | 重启可查；动作与结算完整；写入失败/重试有明确状态 |
| **P1 · 复盘与分支** | 时间线、逐步/跳转/播放、当时观察、原路径与反事实分支 | 已完成；复用 P0 父链与事务，当前默认配置续打 | 回放每节点观察与计分一致；原局只读，新分支不覆盖原路径 |
| **P2 · 引擎多配置与 HTTP 路由** | 多个 LLM、多个 System One；Bridge/Algorithm 参数；四座选择 | 配置规格与 P0 并行；UI/路由使用版本化配置 | 同类型不同配置真实生效且互不污染；历史保存实际版本 |
| **P3 · 模拟对战** | 历史节点续打、正常发牌换边批跑、报告与复盘联通 | P0、P1、P2 的最小闭环；复用现有对战统计 | 可取消、结果入库、报告可打开每副牌；失败/回退归因明确 |

## 3. 配套 AI 研究计划（保留，按需要推进）

下列 M0–M4 / A0.x–A4.x 保留原编号，服务于引擎比较和后续牌力提升，当前执行优先级以 P0–P3 为准。A0 的最小归因/预算接入 P2/P3，其余基线与策略实验按候选需要展开，M4 仍后置。

### M0 · 先让一次实验说得清楚

| ID | 任务与范围 | 验收 |
| --- | --- | --- |
| A0.1 | 统一结果归因：执行失败、实际回退、Mock、确定性动作、搜索/启发式、模型动作分开；细化网络、HTTP、解析、Schema、非法动作、超时和取消 | 模拟成功、唯一候选、原生非法后回退、连接失败及取消；无动作失败单列，不进入“模型输出非法”分母；系统最终合法率与模型原生合法率分开 |
| A0.2 | 核对 `llmEngine` / `llmClient` 与评测入口的排队、重试和取消；建立覆盖排队与全部尝试的决策总预算、整次实验预算及失败后进度持久化 | 用注入客户端和可控时钟复现排队、重试、挂起、流式中断；超预算能终止、释放槽位且不应用迟到动作；记录实际总耗时与各次尝试 |
| A0.3 | 增加请求级计数、逻辑决策 ID、实际请求/重试数、真实模型版本/量化、服务版本；支持显式重试配置、重复 run、实验总量上限与汇总 | 调用次数来自实际请求；零调用不算模型成功；配置与指纹可核对；失败可重放；未采集 usage/服务耗时写缺失，产物无密钥 |

目前归因主要由阶段和 `fallbackReason` 推断，`deterministic` 虽有类型声明却未在执行器落实，已有调用计数不是精确 HTTP 计数。单一总预算不要求不同层默认值机械相同：RPC 还需留回退和通信时间；按阶段配置预算须有测量依据，不能由异常长尾倒推模型计算量。

新实现须同步 [评测方案](ai-engine-model-evaluation-plan.md) 的字段和命令，不先宣称能力完成。默认实验使用受控预算；压力测试显式命名并分表，不靠放大超时掩盖故障。

DDS 的完整信息解只对给定世界、求解目标和规模成立，是残局校准工具，不是普通视角策略的普适最优动作或整局“上界达成率”。暗牌答案可用于离线裁判，但暗牌不能回灌 Actor 输入。

多引擎投票和未经对照的增大搜索预算后置。P2 的多模型配置选择按当前主线交付，新模型的牌力结论仍需对照。每轮保存“质量—延迟—调用量”对照、改善与退化，选择下一项最有证据的变量。

| ID | 任务 | 验收 |
| --- | --- | --- |
| A3.1 | 扩展现有 `match-battle.ts`，接入普通视角 LLM、阶段组合配置、总预算与实际回退链；分开模型原生结果和含回退系统 | 四阶段无暗牌/seed；100 分成功扣底后同步明牌；全 Pass、强制合同、超时、取消和回退均有日志；故障不静默删组来抬高成绩 |
| A3.2 | 扩大换边实战，补座位/发牌者覆盖和合同分层；冒烟后按预声明样本量/预算完成独立确认批次 | 以 `winnerSide` 算赢副，发牌组为统计单位；报告差值、95% 区间、有效组数、干预/故障、庄闲分布；动作可重放 |
| A3.3 | 候选放行与退回；牌力、离线、可靠性和延迟分别判断 | 固定对手、数据、资源预算；原生模型证据不足时只评价含回退系统；实验可保留，默认替换需独立确认 |

十组对战用于回归冒烟。离线候选可先以 100 个独立组诊断，再按目标效果、区间宽度和预算确定确认规模；模型先估算请求量。现有 Hoeffding 区间在 100 组仍很宽，不承诺固定局数足以排序。反复试探后不能挑某次区间不含 0 的报告宣称胜出。

**默认替换门槛**：规则和信息隔离全过；独立确认集上，相对当前实际默认配置的赢副率差 95% 区间下界大于 0；最终动作合法、完成/回退表现达标；目标环境端到端 P95 不超过实验前声明的预算。记录实际默认配置，不能把 CLI 的 `bridge-deep` 自动当作产品默认。提速或离线替换另立等效/非劣协议，不宣称牌力提高。

先对比基线和少量候选，全量 round-robin/Elo 后置。Elo 展示多对手趋势，不能替代配对区间；已有阶段报告也不能替代整副牌确认。

### M4 · 基于证据决定是否训练

| ID | 任务 | 前置与验收 |
| --- | --- | --- |
| A4.1 | 将已有轨迹整理为持久语料：可见观察、合法候选、实际动作、终局、来源、搜索质量与版本 | M0–M3 契约稳定；按整副牌划分、去重；Mock、失败、未评估和低质量标签排除或单列；Actor 输入与全局裁判状态分开 |
| A4.2 | 先做受控监督/蒸馏；Laya 是否可训取决于工具支持，必要时使用独立策略原型 | 教师已通过实战确认；先限定出牌阶段，其他阶段冻结；合法掩码、特征投影、推理耗时和普通视角评测齐全 |
| A4.3 | 蒸馏不足且算力明确后，再做自博弈 RL / 历史策略池 | 基础奖励先用团队终局胜负；密集吃分/成约奖励单独消融，验证不会鼓励虚高叫分；非对称 Critic 的全局信息不进入 Actor 或推理 |
| A4.4 | 导出模型接入 `DecisionEngine`，逐步扩训练阶段与部署 | 模型/特征/规则版本可追溯；非法与异常回退守护；经 M3 同协议验收再决定上线和默认替换 |

已有日志可支撑调试与重放，缺的是来源清楚、质量筛选和集合互斥的训练集。不预设 RL 必然超过搜索，不把研究方案写成已在训练。

## 6. 实验协议与持续门槛

- 分层复用 L0 数据契约、L1 固定场景、L2 配对实战、L3 服务与产品；已有能力不重复立项。旧 E2–E7 统一映射 M0–M4，停止维护第二套编号待办。
- `src/engine/` 保持纯函数；引擎/RPC 接收阶段观察，不接收完整牌局。普通视角不读其他座位暗牌、未知底牌或 seed；100 分明牌只在成功扣底后公开并持续同步。God-mode 结果单列。
- 座位 `0..3` 为东/南/西/北，`seat % 2` 为阵营；A/10 各 10 分、5 为 5 分；分牌不能扣底；闲家锁定线保持 `105−B`；`已吃分 + 未打出分 + 底牌分 = 100`。
- 修 bug 先复现；AI、观察和采样改动保留隔离回归；失败路径显式注入故障，不依赖本地端口状态。
- 任何改动完成前通过 `pnpm test`、`pnpm build`；改 `src-tauri/` 另跑 `cargo check --locked --manifest-path src-tauri/Cargo.toml`。修改独立实验时另验证其配置。
- 复用缓存要求同配置的套件、数据、配置与源码指纹匹配；跨引擎对照记录有意变化的变量，其他协议一致。区间跨 0 写“尚无可靠优势”，缺字段写未采集，不以解释篇幅或回退后的合法率代替模型证据。
