# 保山幺子分 · 游戏 UI 与交互方案

版本：2026-10-14。范围：交互方案、独立可点击原型，以及普通牌桌 / Debug 工作台的首批正式接入。已实现内容、实机截图与验证边界见[接入记录](ui/implementation-validation.md)。

玩家任务、模式规划、功能优先级和体验验收见[游戏产品设计](game-product-design.md)，由项目内[产品经理 skill](skills/product-manager-toolkit.md)辅助整理。本文件继续负责具体 UI 交互规范。

## 1. 选用的开源 UI skill

选用 [UI UX Pro Max](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill)，许可为 [MIT](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/LICENSE)。入口为 [SKILL.md](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill/blob/main/.claude/skills/ui-ux-pro-max/SKILL.md)。本次通过 `skill-installer` 获取到临时目录，实际运行其设计系统、触屏交互与 React 检索脚本；没有修改用户的全局 skill 配置，也没有新增项目依赖。

它适合这个项目的理由是：同时覆盖界面结构、选牌反馈、触屏操作、键盘焦点和响应式布局，可以辅助形成一套跨 Web / Tauri 的规范。纸牌规则、合法操作和信息可见范围仍以本项目引擎为准。

本次检索与判断：

| 检索 | 得到的建议 | 本项目如何采用 |
| --- | --- | --- |
| `card game tabletop tactile --design-system` | 绿金色彩、具有实体质感的游戏界面；同时返回营销展示布局 | 保留青绿与铜金方向；牌桌按游戏流程自主设计，舍弃营销页面结构 |
| `gaming tabletop --design-system`（一次收窄核对） | 泛电子游戏的紫色方案与高成本 3D 效果 | 与地方纸牌游戏、现有皮肤不匹配，不采用 |
| `touch target selection --domain ux` | 触屏目标尺寸、相邻目标间距、移动端点击便利性 | 主要按钮至少 44 CSS px；手牌小屏换行，减少精确点选需求 |
| `keyboard focus dialog --stack react` | 弹窗焦点管理 | 正式接入时焦点进入弹窗，关闭后返回触发入口 |

以上是检索后的人工适配方案，不能将脚本返回的泛用布局当作游戏设计验证。需要长期安装时，可用 `skill-installer` 从该仓库的 `.claude/skills/ui-ux-pro-max` 路径安装；团队复用前固定到审阅过的提交并保留上游许可。

项目已使用的安装包恢复方式、版本记录和本机检索命令见[开发技能清单](skills/README.md)。

## 2. 体验目标与视觉方向

目标用户为熟悉地方玩法的玩家、初次接触的玩家，以及观看 AI 对局和复盘的用户。首屏优先回答：现在轮到谁、我能做什么、双方离胜利还差多少。

设计方向为“青绿牌桌，米白牌面，铜金反馈”。沿用项目已有棋牌主题，让主牌、庄家、选牌状态与队伍目标形成稳定的视觉语言。

| Token / 用途 | 值 | 说明 |
| --- | --- | --- |
| `--page` / 外部背景 | `#F2EFE6` | 暖纸色，适用于菜单、复盘与说明区 |
| `--felt` / 牌桌 | `#174D3D` | 青绿，牌桌大面积使用 |
| `--deep` / 牌桌深色 | `#103B30` | 操作区、牌桌边缘 |
| `--cream` / 牌面、桌上文字 | `#FFFAF0` | 与桌面形成清晰分离 |
| `--gold` / 主操作、选牌边框 | `#E9C780` | 铜金，按钮使用深色字 |
| `--text` / 浅色区正文 | `#243D34` | 保持长文本可读 |
| `--muted` / 浅色区辅助文字 | `#5C6C61` | 用于辅助说明，避免低对比浅灰 |
| `--red` / 红花色 | `#AF303C` | 仅在浅色牌面使用；深色牌桌上的花色与名称同显 |

标题采用系统宋体 / 衬线字体，正文使用系统中文无衬线字体；数字采用等宽数字特性。原型无需联网加载字体或图片。正式接入将这些角色映射到 `src/styles/tokens.css` 与现有皮肤变量，继续支持经典棋牌、森林绿和午夜蓝。

## 3. 信息架构与牌桌布局

```text
顶栏：游戏名称 | 南北胜副 2 : 1 东西胜副 | 第 4 副 · 先胜 5 副

┌─────────────────────────────┬─────────────┐
│ 主牌 / 轮次 / 庄家合同        │ 本副吃分     │
│            北家（搭档）       │ 庄家 35/85  │
│                             │ 闲家 15/20  │
│ 西家       本轮出牌      东家 │ 分数守恒     │
│                             ├─────────────┤
│ 当前行动提示 + 当前主操作      │ 公开行动记录 │
│ 你的手牌 / 选牌预览           │ 上一轮/历史  │
│ 南家（你）                   │ 规则/设置    │
└─────────────────────────────┴─────────────┘
```

- 顶栏展示整场“胜副”，本副侧栏展示“吃分”，文字中保留单位。
- 座位保持真实方位：默认玩家南家在下，北家搭档在上，东家在右，西家在左。序号仍为东/南/西/北 `0..3`，不得因 UI 排列修改队伍映射。
- 轮到谁同时通过头像边框、文字与操作提示表示；AI 等待不使用假的倒计时。
- 本轮出的牌带玩家名称，行动顺序有文字提示；吃分入账只在四家完成一轮后更新。
- 主操作紧贴手牌区域。叫分和定主是同层级选项组；扣底、出牌和结算各有一个明确主按钮。
- 对局历史、观战、皮肤保留入口；设置中的玩家参数和开发者选项继续分层。

## 4. 阶段交互契约

| 阶段 | 显示内容 | 用户操作 | 提交、反馈与边界 |
| --- | --- | --- | --- |
| 叫分 | 当前最高分、当前行动者、自己的 12 张手牌、公开叫分记录 | 从引擎提供的合法档位叫分，或不叫 | 档位以 5 分递增，70 起、100 止；点档位即提交，提交后禁重复点击；四家都不叫时提示“无人叫分，重新发牌” |
| 定主 | 庄家身份、自己的各门张数与分值 | 点击一门花色确定主牌 | 花色同时有符号和中文名；提示“张数最多”仅为统计，不直接宣称最优；定主后展示庄家拿底过程 |
| 拿底 | 庄家看到具体底牌与入手反馈；其他座位仅看到拿底公开动作 | 查看后进入扣底 | 庄家手牌由 12 到 16；来源牌带“底”标记；普通玩家视角不能看到别人底牌 |
| 扣底 | 16 张手牌、禁选分牌、已选四张预览 | 点牌选择或取消；推荐填充选择；清空；确认 | A / 10 / 5 禁选并说明原因；不足四张不能提交，满四张后第五码提示先取消；推荐只选牌不提交；成功后剩余 12 张 |
| 出牌 | 领出花色、当前最大牌、本轮分数、合法牌、自己的手牌 | 默认点牌选中，再点同牌或主按钮确认；换牌只更新选择 | 有领出花色必须跟同门；缺门时可杀或垫牌，不能强迫用主牌；非法牌不提交并说明原因 |
| 一轮入账 | 收牌玩家、本轮得分、双方累计吃分 | 自动推进或按当前节奏继续 | 四家出完后才计分、判定锁定线；胜者下轮领出；得分动画不承担业务推进职责 |
| 本副结算 | 成局 / 不成、合同、双方吃分、底牌分、未打出分、整场比分 | 下一副；查看复盘 | 提前锁定时保留全部余牌，停用出牌；已吃 + 未打出 + 底牌 = 100；常规流程不默认自动开下一副 |
| 整场结束 | 获胜队伍、最终胜副、先胜目标 | 再来一场；对局历史 | 替换“下一副”主操作；不能在整场结束后继续当前副 |

正式游戏沿用玩家已有的“出牌确认”设置：开启为二次确认，关闭为点牌即出；调试模式强制确认须如实展示。原型固定演示二次确认，不提供设置开关。

## 5. 手势、键盘与牌面状态

| 状态 | 视觉 | 语义与动作 |
| --- | --- | --- |
| 合法未选 | 正常牌面，点按有反馈 | 可点击，名称包括花色、点数、分值 |
| 已选 | 牌面上抬、铜金边框、“已选”文字 | `aria-pressed=true`；不只依赖颜色 |
| 跟牌非法 | 不透明灰色牌面 | 禁止出牌；显示“须跟黑桃，本轮不可出”等原因 |
| 扣底分牌 | 不透明灰色牌面 | 禁止扣底；说明“分牌不能扣底” |
| 等待其他玩家 | 正常牌面 | 当前不能行动，但不误标为规则非法 |
| 主牌 / 分牌 / 摸入底牌 | “主”、分值、“底”文字标记 | 保留花色与点数；标记不覆盖牌面 |

点按是主路径；拖牌不作为必须掌握的手势。主按钮至少 44 CSS px 高、相邻操作尽量留 8 px 间隔。大屏叠牌优先保留至少 44 px 的可点击区域；空间不足就换行。不能通过不断增加遮叠隐藏点数，也不能只靠 hover 看牌。

键盘使用 Tab 移动、Space / Enter 激活选牌或确认；输入框和弹窗打开时禁用牌桌快捷键。正式游戏继续保持已有快捷键约定，明确焦点位置，弹窗关闭后归还焦点。原型使用原生按钮与下拉框，可通过这些标准键盘操作访问全部核心流程。

## 6. 100 分局与信息可见范围

以南家为庄家的示例：叫分、定主和扣底阶段，北家只能显示头像、张数和公开行动。**只有成功扣底后**，在北家头像附近出现“搭档明牌 · 所有人可见”，并展示北家剩余手牌。之后每次北家出牌，公开牌区同步减少；庄家 / 玩家视角发生变化时仍绑定实际座位。

正式游戏必须复用合法观察投影与 `RevealedHand`，不能将完整 `hands`、未知底牌或 seed 传给决策引擎。明牌条件不能只判断 `bid === 100`，也不能在扣底选满四张、请求正在提交、提交失败时提前公开。

本副进度同时显示两条线：庄家 `B`，闲家 `105 − B`。例如叫 85 分，庄家 85 分成局、闲家 20 分破庄；叫 100 分，庄家 100 分成局、闲家 5 分破庄。整数阈值不得改为 `101 − B`。

原型所有牌均为固定虚构样例，没有真实对局数据。阶段选择器可以直接进入“出牌 / 结算”的已扣底样例；从“扣底”流程进入时则必须完成成功提交才明牌。原型明牌区以文字简化表示，正式界面使用现有扑克牌组件。

## 7. 观战、复盘与失败反馈

玩家入口与核心玩法相邻，以下能力在正式接入时复用现有逻辑；原型演示主玩法与 Debug 的核心操作，观战和完整复盘尚未接入。

| 场景 | 交互设计 |
| --- | --- |
| 观看 AI 对局 | 暂停 / 继续、下一步、速度与退出常驻；点头像查看真实决策理由，点牌查看，按现有规则自动暂停；普通对战与观战可见范围分别遵循现有契约 |
| 对局复盘 | 使用独立复盘工作区，显示所在副、轮次和阶段；切座位观察、跳转、分支能力保持现有功能；全牌复盘显示不得扩散到 AI 输入 |
| AI 等待与降级 | 显示当前行动者与计算状态；请求失败时展示真实回退结果并继续合法决策；不能将“服务失败”表现为对手已出牌 |
| 保存失败 | 保留顶部保存状态；按现有策略暂停自动推进，提供“重试保存 / 导出待保存记录”；成功后由用户继续 |
| 选择被取消 | 切副、切阶段、切座位或取消旧请求时清除失效选择，避免提交前一阶段的牌 |
| 重新开局 | 从菜单发起时说明会放弃当前副，保留返回入口；“下一副”无需额外确认弹窗 |

## 8. 响应式与动效

原型采用独立页面的自适应布局：宽屏牌桌 + 右侧信息区；中屏信息区移到牌桌下方；小屏手牌六列换行，页面允许自然纵向滚动。扣底的 16 张牌常规八列两行，小屏六列三行。不得裁掉主操作或通过缩小到不可点的牌面强行塞入一屏。

正式游戏已经使用 `LandscapeViewport` 支持横屏及竖屏旋转。本次不修改方向策略。实际接入时按它的**内部容器宽高**适配，而不是直接复制原型的 viewport 媒体查询；优先保证手牌、行动区、四家位置完整，再折叠日志和工具。方向变化不能重建对局或丢失选牌，并保留物理安全区。

建议验证尺寸：375×812、768×1024、1024×768、1440×1000，以及正式容器的 844×390；字号放大 200% 时仍可访问所有关键操作。

选牌反馈约 120–160 ms；出牌移动约 180–240 ms；收牌得分按现有速度设置呈现。动画只用 transform / opacity，遵循减少动态效果偏好；胜负判断、入账和取消请求不得依赖动画完成回调。

## 9. 组件落点与实施顺序

| 现有模块 | 后续接入职责 |
| --- | --- |
| `Scoreboard` | 整场胜副、先胜目标、本副序号 |
| `ControlPanel` | 各阶段提示与主操作，不承担规则判断 |
| `HumanHand` / `CardView` | 合法、选中、禁用、主牌 / 分牌 / 底牌标记与触屏排布 |
| `OpponentSeat` / `SeatActivity` | 行动者、身份与公开行动反馈 |
| `TrickArea` / `ActionPresentation` | 本轮牌、收牌与得分展示 |
| `RevealedHand` | 100 分成功扣底后的公开余牌 |
| `GameTools` / `SpectatorControls` | 玩家工具与观战节奏 |
| `HandResultModal` / 历史相关组件 | 本副与整场结算、复盘入口 |
| `LandscapeViewport` / 主题变量 | 方向适配、安全区与现有皮肤兼容 |
| `SquareTable` / `DebugSidePanel` | 四座方位与逐座看牌、强制确认、单步推进、五页诊断工作台 |
| `useGame` / 决策游标 | 进入调试暂停、建议和执行分开、撤销恢复后取消旧请求与旧建议 |

第一步：接入色彩、信息层级、牌面可读性和工具折叠；不改规则。第二步：逐项落实选牌反馈、扣底预览与移动容器布局，同时保证 Debug 单步、逐座看牌和诊断入口完整。第三步：观战 / 复盘统一设计语言，完善网络失败和保存失败的可访问反馈。每项行为变化按仓库要求先写回归测试，再实现。

验收重点：跟门强制与缺门可垫牌；扣底分牌禁选和恰好四张；二次确认与快捷出牌设置；等待 / 动画期间重复点击；100 分明牌时机与持续同步；`105 − B` 锁定阈值；提前结算余牌与分数守恒；弹窗焦点和触屏命中范围；保存失败显式注入；普通玩家、观战、全牌复盘与 AI 信息隔离。

## 10. 原型使用与验证

入口：[可点击原型](ui/interaction-prototype.html)。这是一个无依赖的独立 HTML，可直接用浏览器打开，也可在 `pnpm dev` 下访问 `/docs/ui/interaction-prototype.html`。它不被正式游戏入口引用，生产构建不会将它作为玩法页面发布。

截图：[桌面选牌预览](ui/prototype-desktop.jpg) · [手机选牌预览](ui/prototype-mobile.jpg) · [Debug 工作台](ui/prototype-debug.jpg)。图片用于展示，完整操作以 HTML 原型为准。

体验路径：

1. 默认“出牌”阶段：点击黑桃 A → 查看选中反馈 → 再点同牌或点击“出 A♠”。灰色牌无法出牌；出完演示等待东家，不继续模拟 AI。
2. 切“叫分”：点击档位 → 点击主牌花色 → 选扣底四张 → 确认扣底 → 庄家首轮领出。
3. 切“扣底”：试点分牌、选三张、选四张、尝试选第五张；使用推荐与清空对比反馈。
4. 将叫分样例切为 100 分，在叫分 → 定主 → 扣底中观察搭档隐藏，成功扣底后明牌；切回扣底应再次隐藏。
5. 切“结算”：查看庄家锁定线、分数守恒、整场比分增加与保留余牌；“体验下一副”回到独立叫分样例。
6. 将“牌桌模式”切为“Debug 调试”：展开东家手牌，对照“AI 阶段观察样例”保持不变；获取建议 → 应用 → 撤销 → 恢复。也可以用“获取待执行动作”准备，再用同一主按钮执行。
7. 切换五个诊断页签；候选只填充选牌，仍需确认。页签支持左右方向键、Home / End。从叫分开始可以应用建议推进定主、扣底，再逐步撤销到原阶段。

阶段切换会重置固定样例，结算样例与出牌样例互相独立。“不叫”只演示让出行动权；完整无人叫分重发牌、AI 后续出牌、持续明牌同步、上一轮回看、观战 / 完整复盘、网络错误、整场结束与快捷出牌设置由本方案规定，尚未在原型中模拟。Debug 中的建议、观察字段与诊断都是固定展示样例；真实引擎评估、自动连续推进、种子重开、快照导入导出和请求审查继续由正式版承担。

回归测试位于 `tests/ui-design-prototype.test.ts`。测试先确认“选牌未生效”“扣底未切阶段 / 缺少叫分操作”“100 分扣底后未明牌”“结算比分未更新”等目标行为失败，再完成实现并验证通过。Debug 测试先因缺少模式、看牌、建议执行与页签响应失败；跨阶段撤销测试先因叫分后撤销按钮仍禁用失败，再实现并验证通过。导入路径环境错误已单独修正，不计入测试先行证据。交付仍需执行 `pnpm test` 与 `pnpm build`。

## 11. 桥牌成熟产品参考

参考依据为以下产品的官方使用文档，核对日期为 2026-10-14；没有将未登录体验的线上界面称作实机评测。开源 UI skill 用来整理视觉与可访问性，桥牌产品用来校验四人吃墩游戏的操作习惯。以下“本项目采用”是针对幺子分的设计判断。

| 参考产品与依据 | 成熟交互 | 本项目采用 |
| --- | --- | --- |
| [RealBridge 玩家指南](https://realbridge.online/player-guide.html) | 轮到谁以姓名高亮表示；当前墩牌在桌中央；支持单击、两次点按等输入方式 | 四座方位固定，行动者用边框和文字双重提示；桌中央展示本轮公开牌与出牌者；沿用已有出牌确认设置，Debug 强制确认 |
| [Funbridge 玩法指南](https://funbridge.com/faq/how-to-play) | 南家玩家视角、黄色行动箭头、领出花色预选、合同与目标进度、结果进入回放 | 玩家南家在下、搭档北家在上；合法跟门牌突出；常驻主牌、庄家合同和双方吃分目标；结算保留复盘入口 |
| [RealBridge 回放与分析](https://realbridge.online/double-dummy-and-explore-play.html) | 已完成牌局逐牌 / 逐墩回放，可以探索另一条出牌路线 | 正式复盘保留步进与分支；Debug 候选、执行与历史分区，同一游标关联评估；全牌分析明确标注信息范围 |
| [BBO 撤销规则](https://help.bridgebase.com/hc/en-us/articles/1500007912702-When-can-I-ask-for-an-Undo-and-or-Redeal) | 对局撤销用于误点，并受玩法 / 赛事设置限制 | 日常对战通过出牌确认减少误点；Debug 的撤销 / 恢复属于沙盒能力，不能把它包装成普通对战随意改牌 |

具体落地规范：

- 牌桌是视觉中心。主牌、合同、行动者始终可见；帮助、设置和长日志放到侧栏或抽屉，不能压住当前操作。
- 普通模式提供“上一轮”公开回看：保持四座方位，列出四张已出牌、胜者和分值，关闭后回到原来的手牌焦点；回看不改变当前对局、不暴露余下暗牌。完整历史再进入独立复盘。
- 正式 Debug 继续使用 `SquareTable` 的 1:1 方位牌桌；原型的四座看牌卡片是便于比较可见性的简化列表，不代替正式版的四座牌图。
- 桥牌的常规明手不能直接搬入幺子分：只有 100 分成功扣底后的庄家搭档明牌。桥牌的定约、墩数、将吃与计分含义，也不能替换本游戏的叫分、跟门与吃分规则。
- RealBridge 的双明手分析可借鉴操作组织；分析时已知全牌的结果不能冒充本项目运行中 AI 的合法信息胜率。Funbridge 的单张自动出牌也不用于 Debug，单步和确认保持可控。

## 12. Debug 模式完整交互

正式版页头提供“进入 / 退出 Debug”，设置中的“开发者选项”仍可调整工程参数；原型顶部单列模式切换，方便评审。调试工作台复用当前 `DebugSidePanel` 能力，不新增另一套决策状态机。

| 区域 | 交互契约 | 原型覆盖 |
| --- | --- | --- |
| 模式与节奏 | 进入即暂停；单步 / 自动 / 暂停按现有状态显示；出牌强制确认，Space 单步、Enter 确认或推进 | 进入暂停、单步先准备再执行、出牌确认；使用原生按钮键盘操作，未模拟自动播放 |
| 四座看牌 | 默认只展开人工座位；逐座显式展开；临时看牌不按花色泄露未展开手牌；退出清理临时看牌 | 四座独立开关；收起自己的手牌时清除选牌；退出 / 再进入恢复默认 |
| 规则明牌 | 100 分成功扣底后搭档明牌不可收起，始终同步；退出 Debug 后仍保留 | 展示不能收起的规则明牌；与“调试可见 · 不传给 AI”分别标记 |
| 建议与执行 | H / 获取建议只评估；准备动作可以人工确认或显式应用；候选点击只选牌 | 固定样例建议、显式应用、候选选牌；不伪造思考文本或胜率 |
| 撤销与恢复 | Z / Shift+Z 回退或恢复；使旧请求和旧建议失效；R 按现有重开契约处理 | 可撤销 / 恢复叫分、定主、扣底和出牌；阶段重置清空历史与旧建议 |
| 思维推演 | 真实计算状态、引擎结论和请求审查；字段无值则不显示估计值 | 演示建议状态与合法观察；清楚注明未调用真实 AI |
| 候选比选 | 本阶段合法候选；评估存在时显示胜率 / 期望分 / 来源，无值不补零 | 出牌合法候选与牌面分值，点击填充选择 |
| 绝门记牌 | 只由公开出牌历史推断缺门；展示分数守恒与锁定阈值 | 无证据标“未知”；看暗牌不改变推断，显示双方目标和守恒式 |
| 历史追溯 | `sessionId / nodeId / epoch / configRevision` 关联历史与诊断；分支评估绑定同一位置 | 样例版本、可撤销 / 恢复步数、当前阶段 |
| 沙盒工具 | 保留种子重开、快照导入导出、起点回放、四座引擎配置 | 页签解释正式能力；样例撤销 / 恢复可操作 |

布局：宽屏牌桌左侧、工作台右侧；中屏工作台移到桌下；窄屏按“当前动作 → 诊断页签 → 观察详情”纵向排列。单步主按钮常驻工作台顶部，观察详情折叠，候选操作至少 44 px 高。页签左右键切换、Home / End 到首尾，选中状态和焦点分开表达。

信息边界必须由数据投影保证：调试看牌集合仅供 UI 使用；决策请求仍来自阶段观察，禁止借四座看牌读取完整暗牌、未知底牌或 seed。撤销、改配置、切阶段或重开后，以新游标丢弃旧响应。100 分的规则明牌属于合法公开信息，须进入相应观察并持续同步。

验收时同时检查两条路径：开启东家临时看牌前后，AI 请求字段保持不变；100 分成功扣底后，AI 观察新增合法搭档明牌且退出 Debug 不隐藏。另检查失效请求、重复应用、撤销再评估、收起手牌后选牌清理，以及只依靠公开历史的绝门判断。
