# 文档维护约定

文档解释当前代码和明确的候选方案；源码、配置与实际测试是事实来源。入口见[文档索引](../README.md)。

## 单一职责

| 位置 | 维护内容 |
| --- | --- |
| 根 README / AGENTS | 最短启动与导航 / 开发约束 |
| TODO / planning/development-roadmap | 近期导航 / 任务状态与下一步 |
| guides / features / architecture | 使用方法、当前行为、边界与模块落点 |
| ai / design / planning | 评测方法、算法原理、产品取舍和候选验收 |
| maintenance / skills | 持续维护约定、工具安装与项目技能源码 |
| ui | 交互规范与仍有用途的原型资源 |

## 更新与删除

- 代码或命令变更时更新同主题文档；协议字段直接链接类型定义，不抄写第二套接口。
- 新内容优先并入现有主题。替代旧说明时同步更新入链，删除失效内容，不另建 v1/v2、旧路径跳转页或重复归档。
- 已完成的评审、逐次验收、技能使用过程、一次性计划和历史成绩不长期放入 docs；可复用结论整理到规范、当前说明或回归测试。
- 不把设计目标写成已实现，不把小批实验、Mock、接入成功或原型截图写成牌力/产品收益证明。
- 固定评测样本与测试夹具属于源码输入，保留；报告、请求响应、检查点和临时截图属于输出，默认忽略。
- 引擎结论必须能追溯到实际证据。结果清理后不继续保留依赖它的胜率、延迟和排名声明；需要长期保存证据时先明确归档位置与范围。
- 用户数据、配置和密钥按[文件管理约定](git-tracking-policy.md)处理，普通整理不清理玩家历史库。

## 交付检查

检查本地 Markdown 链接、图片与源码路径，确认删除内容没有被测试或运行代码读取。按照 [AGENTS.md](../../AGENTS.md) 运行检查，交付说明报告实际结果；不要再创建一篇只记录这次整理过程的文档。
