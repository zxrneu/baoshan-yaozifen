# P3 · 独立模拟、换边批跑与复盘报告

> 文档类型：当前实现说明；交付日期：2026-10-13，内容复核：2026-10-14。P3.1–P3.3 已实现；历史 JSON 协议 2 / SQLite schema 5，规则 `basic-v1`。返回[文档索引](../README.md)。

未替换默认引擎，不据此宣布牌力排序。

## 玩家入口

- 对局历史 → 模拟对战：选择东/南/西/北四座配置、发牌种子与总组数、并发、单步/总预算、动作/重发牌上限，启动全生命周期或固定前三阶段的换边对战。
- 历史复盘 → 配置四座独立续打：从当前保存节点启动一个新的持久分支。运行有独立会话身份，原节点、原后续、原副摘要与活动牌桌不变。
- 报告支持刷新、取消、续跑，并可打开每组两局的具体历史分支复盘；关闭窗口不取消服务端运行。取消会保留已提交动作和已完成副牌。

四座只能选择配置，模拟不等待 Human 输入。全生命周期首局 A 坐东西、B 坐南北，次局交换 `0↔1、2↔3`；四座可使用不同配置。种子集合使用指定起始 seed 加 `137 × 组号`，HTTP 也支持传入完整不重复种子清单。

固定前三阶段由独立指定的共同配置完成首局叫分/定主/扣底，次局直接重放同一组开局动作，因此两局合同、主牌、底牌和出牌起点相同。重放标为确定性动作，关联原评估，不冒充第二次模型调用。成功扣底后座位配置切换为各自出牌配置。两种协议各自保存、各自显示报告，不混算。

## 保存、恢复和预算

`simulation_runs` 保存冻结请求、全部实际及备用配置版本、源码指纹、独立搜索 seed、预算进度和状态。`simulation_boards` 以 `(run_id, board_index)` 唯一保存组进度、两局引用、结果与故障。稳定组/副/分支/动作身份避免重复计数；逐动作仍经现有历史事务写入，动作、当时观察、实际配置与结算一起提交。

- 每次启动最多 1,000 个独立发牌组（2,000 副），并发 1–8 组，每副 1–4,096 动作，重发上限 0–20。达到重发上限保存这次重发并终止该副，**不强制叫分**。
- 决策总预算覆盖排队、上游重试、主/备用引擎；模拟总预算独立限制整个运行。挂起且忽略 signal 的 Promise 也能被取消/预算终止，迟到动作不能提交。
- 单副决策失败会记录故障并继续其他副；存储基础设施失败会取消其他并发组，等待所有工作结束后报告失败。
- 续跑从实际历史分支游标读取，已完成副牌跳过；提交成功但组摘要未更新时也能恢复，不依赖内存计数。已失败尝试保留，恢复后不会删除故障来美化统计。
- 服务重启后，旧 `running` 状态显示为可续跑的中断状态，显式续跑。累计总预算不重置；异常中断按保存的开始时间保守计入停机时间，避免重启绕过预算。
- 续跑需要相同源码/规则/配置实现。旧配置和备用链从历史库解析，环境端点变化时明确拒绝执行；只读报告不依赖模型服务在线或端点恢复。

搜索随机源独立于发牌 seed。每次 run 保存随机搜索 seed，按组、局及动作序号派生搜索随机源，注入 Bridge PIMC 和 Algorithm 的采样器，不放入阶段观察。时间预算和模型服务本身仍会带来运行差异；固定随机源不宣称整局模型输出完全确定。

## HTTP 与报告

- `POST /api/history/simulations`：接收 `SimulationRequest`，返回 202 和运行报告；四座引用必须同时包含 `profileId` 与 `version`。
- `GET /api/history/simulations`：最近 100 次运行。
- `GET /api/history/simulations/:runId`：读取进度与报告。
- `POST /api/history/simulations/:runId/cancel`、`.../resume`：取消或续跑。
- 副牌仍经 `/api/history/hands/:handId` 校验读取，`branchId` 指向对应路径。

报告复用 `scoreDuplicateBoard` 与 `pairedWinRateInterval`：主指标是实际赢副率差，95% 保守 Hoeffding 区间以发牌组为独立样本。只有两局都完成的组进入配对统计，失败、未完成组继续列出。历史续打只显示分支结果，不参与换边比较。累计吃分不用于判定赢家，小样本和区间跨零不裁定引擎排名。

同时显示合同与成约、未打出分、耗时 P50/P95、模型/搜索/启发式/确定性来源、实际备用引擎回退、原生非法、无动作失败。系统最终合法率与原生模型输出合法率分开；无输出的网络、HTTP、解析、超时、取消、执行故障独立记录，不能归入原生非法分母。所有备用都失败也保存各次尝试的配置与失败归因，不冒充已执行回退。模型 HTTP 请求/重试次数现已持久化并显示在报告中；usage 与服务分段耗时仍属于 A0.3 待补范围。

## 请求级统计协议

模拟实现版本为 `simulation-v2:basic-v1:profiles-v1:requests-v1`；历史 JSON 协议 2、SQL schema 5 不变，新增统计存入现有 JSON 列。旧运行可只读查询，缺字段显示未采集；续跑继续要求源码和模拟实现版本一致。

每次逻辑决策创建独立请求收集器，经 `DecisionService` 向主配置与各备用配置传递 `onModelRequest`。LLM SDK / Fetch 和 System One 的实际 HTTP 传输点报告尝试；SDK 内部重试、连接失败与 HTTP 失败均计数，流式 token 不增加请求数。收集器只保存配置身份和次数，不保存密钥、请求正文、其他座位暗牌或发牌 seed。

- 成功动作的 `evaluation.recommended.requestStats` 随动作在同一事务保存。
- 无动作失败的 `SimulationFault.requestStats` 随故障保存，包含已发起但随后超时/取消的请求；全部备用失败也保留每个配置的尝试。HTTP 已完成但动作提交失败时，统计也随存储故障保存，且保持 `decisionFailure: false`，不混入无动作引擎失败。
- `requestStats.protocolVersion = 1`，包含独立 `logicalDecisionId`、`modelRequestCount`、`modelRetryCount`、`invocations`。各 invocation 保存配置引用、引擎类型、请求/重试数和 HTTP 尝试序号。续跑同一个节点失败后的新决策使用新 ID；报告保留原失败请求。
- 唯一候选、固定开局重放和离线动作记录 0 请求。未声明并提供遥测的模型客户端、旧记录缺字段写 null，不推断为零。迟到结果不能修改已保存的统计或提交动作。
- `summary.decisions.actualModelCalls` / `actualModelRetries` 从数据库中的动作评估与无动作故障汇总；`requestDecisionCount` 是确认至少发起一次 HTTP 请求的逻辑决策数，重试不重复算决策；`unmeasuredRequestDecisions` 单列未采集项。有未采集项时总请求/重试数为 null。按 `logicalDecisionId` 去重，事务已提交后报错时不会与故障中的同一统计重复计数。重复读取、已完成动作和无新增决策的续跑不重复累计。

## 回归证据和边界

测试先确认缺失入口返回 405、历史/固定模式被拒绝、挂起请求未终止、全部备用失败丢失原生非法归因、随机采样无法重现、报告错误依赖模型环境、固定开局座位配置错误、并发存储失败后其他组未取消，再实现相应行为并验证通过。

请求统计测试先复现报告缺失请求/重试字段和 UI 缺失 HTTP 计数，再接入回调与持久化。覆盖 SDK 重试、主/备用全失败、成功备用动作、并发组隔离、固定开局零请求、旧记录未采集、动作事务提交前/后存储故障、临时数据库重启与取消续跑，取消后的迟到动作不入库；请求统计不含密钥或 seed。

覆盖真实 SQLite 与 HTTP、四座同类型不同版本及换边路由、100 分明牌更新和暗牌/seed 隔离、原路径/全局日志不变、取消迟到动作、临时文件数据库重启续跑、重发及参数上限、报告取消/续跑/逐副复盘。外部模型测试通过注入故障完成，不依赖默认端口或真实模型在线；小批跑验收只证明工程闭环，不证明牌力提升。

原生 Tauri 无 Node 服务历史、跨主机分布式执行、多服务进程同时持有同一运行、usage/服务分段耗时及大规模排名尚未支持。本实现使用单个 Node 服务进程协调运行。
