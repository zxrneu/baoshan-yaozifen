## 熟人联机演进

用户已选择熟人约局、P2P 与低服务器成本优先。详细边界和验收见[联机方案](multiplayer-and-monorepo.md)，按依赖逐步推进：

1. 复用当前规则、观察和会话，定义网络命令、逐座位视图与房间身份；先验证双客户端的一致性与信息边界。
2. 接入轻量房间/信令，验证 WebRTC IPv6/IPv4 直连；以真实 ICE 结果判断，提供中继兜底和成本观测。
3. 完善邀请组局、断线重连、房主离开、AI 替补及真人归座。
4. 按实际需求增加文字/语音、公开大厅或服务器权威模式；先明确隐私、风控与运维预算。

本地 GameSession 和决策 API 尚不等于多人权威对局；这些候选不表示已实现或已经部署。

## 产品与 AI 候选

- 依据具体牌局修复叫分、扣底、搭档配合等失误，先加入规则/策略回归，再选择最小足够的评测。
- 定主、扣底、目标线教学和阶段提示按玩家任务推进；真实新手收益仍需观察，不能只凭界面接入判断。
- AI 已有开发/保留场景和请求归因；独立发牌确认、服务版本/usage/分段耗时及 CLI 的 LLM 实战能力按问题补充。
- 训练与蒸馏先具备可用语料、可靠教师、独立验证和算力预算，再决定是否开展，不预设更大模型或搜索一定更强。

研究编号与验收见 [AI 研究规格](ai-research.md)；平台、分发、规则变体等见[后续方向](future-directions.md)。不将整批研究准备作为普通产品改动的统一前置。
