## 近批执行顺序

1. **A0.3 补测量与归因**：优先让每次模型/模拟结果的请求量、实际版本和缺失字段可追溯，复核总预算与错误分类。
2. **A1.1–A1.3 冻结数据与基线**：完成裁判审查、保留集和受控重复运行，再决定策略候选。
3. **A2.x → A3.x 验证候选**：按可复现的决策问题开展小范围修复/消融，用独立整副牌确认收益；不重复建设已有 P0–P3。
4. **产品与平台按具体需求立项**：候选范围见[后续方向](future-directions.md)；训练遵守 M4 前置。

这是一组候选推进顺序，没有固定日历工期，也不表示已授权调用真实模型、训练或发布。

## 持续交付门槛

- 规则与信息隔离遵守 [AGENTS.md](../../AGENTS.md)；功能和修复先写行为回归，故障显式注入。
- 完成任何改动前跑 `pnpm test` 和 `pnpm build`；Tauri 和独立实验按所改范围追加检查。
- 普通 AI/RPC 不读取其他暗牌、未知底牌或 seed；100 分明牌在成功扣底后才公开并持续同步。
- 默认引擎替换须通过[统一评测](../ai/evaluation-plan.md)。记录当前真实默认配置，在独立确认集上检验赢副差区间、可靠性与目标环境 P95；提速和牌力提高分别举证。
- 缺失统计显示未采集，失败组不静默删除，历史结论引用固定 run 与指纹。每项交付同步当前入口和功能说明；文档分工见[治理规则](../maintenance/document-governance.md)。
