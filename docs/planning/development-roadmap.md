## 近批执行顺序

1. **结算直接复盘（产品设计 D2 / UX-04，已交付）**：本副及本场结果页通过稳定历史身份打开本副原动作记录；保存未完成、失败或历史不可用时明确反馈。复盘无需再次调用模型，打开与关闭保留活动牌局。
2. **独立单副练习（产品设计 D2 / UX-05，已交付）**：顶栏入口使用独立会话与 `targetWins=1`；一副正常或提前锁定结束后均完成练习。练习有独立历史身份与待保存队列；四座选择与调试偏好不覆盖标准对局。退出回到原标准对局并保持暂停，同页返回保留原会话；刷新后按已有历史恢复机制处理。
3. **依据具体产品问题继续迭代**：AI 的叫分/扣底/搭档配合失误修复（A2.x）、阶段提示与短教学（B5 / T1.5）保留为后续候选。功能和缺陷修复按 TDD 验证，复用已有历史、复盘、配置与模拟入口。
4. **研究按具体目标启动**：A1 数据/基线、A3 独立对战确认及 A4 训练在所选问题需要时推进；不再把整批研究准备排在所有产品改动之前。牌力收益与默认引擎替换仍须相应评测证据，训练遵守 M4 前置；在线与分发候选见[后续方向](future-directions.md)。

本轮取舍：跳过配置/代码/数据指纹追溯扩展、重复运行管理、请求总量与时间预算治理；输入/输出 token、模型/服务版本及分段耗时采集继续延后。上述工作不作为近期产品切片的统一前置，未采集字段仍明确缺失。

“游玩更方便”首批两项已交付；后续候选没有固定日历工期，也不表示已授权调用真实模型、训练或发布。

## 持续交付门槛

- 规则与信息隔离遵守 [AGENTS.md](../../AGENTS.md)；功能和修复先写行为回归，故障显式注入。
- 完成任何改动前跑 `pnpm test` 和 `pnpm build`；Tauri 和独立实验按所改范围追加检查。
- 普通 AI/RPC 不读取其他暗牌、未知底牌或 seed；100 分明牌在成功扣底后才公开并持续同步。
- 默认引擎替换须通过[统一评测](../ai/evaluation-plan.md)。记录当前真实默认配置，在独立确认集上检验赢副差区间、可靠性与目标环境 P95；提速和牌力提高分别举证。
- 缺失统计显示未采集，失败组不静默删除，历史结论引用固定 run 与指纹。每项交付同步当前入口和功能说明；文档分工见[治理规则](../maintenance/document-governance.md)。
