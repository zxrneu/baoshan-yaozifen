# AI 研究候选与验收

> 文档类型：研究规格；整理日期：2026-10-14。任务状态与近批顺序统一见[开发路线](development-roadmap.md)，实验协议见[统一评测](../ai/evaluation-plan.md)，返回[文档索引](../README.md)。

以下保留 M0–M4 / A0.x–A4.x 编号、研究范围和验收条件。它们不阻塞已经交付的 P0–P3；每轮按明确候选开展，不预设训练或更大搜索必然提高牌力。

## M0 · 先让一次实验说得清楚

| ID | 任务与范围 | 验收 |
| --- | --- | --- |
| A0.1 | 统一结果归因：执行失败、实际回退、Mock、确定性动作、搜索/启发式、模型动作分开；细化网络、HTTP、解析、Schema、非法动作、超时和取消 | 模拟成功、唯一候选、原生非法后回退、连接失败及取消；无动作失败单列，不进入“模型输出非法”分母；系统最终合法率与模型原生合法率分开 |
| A0.2 | 核对 `llmEngine` / `llmClient` 与评测入口的排队、重试和取消；建立覆盖排队与全部尝试的决策总预算、整次实验预算及失败后进度持久化 | 用注入客户端和可控时钟复现排队、重试、挂起、流式中断；超预算能终止、释放槽位且不应用迟到动作；记录实际总耗时与各次尝试 |
| A0.3 | 实际 HTTP/重试计数、逻辑决策身份与主/备用尝试跨重启汇总；真实模型版本/量化、服务版本、usage、服务分段耗时；显式重试配置、重复 run 和实验总量治理 | 调用次数来自实际请求；零调用不算模型成功；配置与指纹可核对；失败可重放；未采集 usage/服务耗时写缺失，产物无密钥 |

场景评测已在 LLM SDK/Fetch 与 System One 的实际 HTTP 传输点计数，重试单列；唯一候选落实 `deterministic`，未返回动作的异常落实 `execution-failure`，不冒充回退。注入客户端未提供统计时写 null；配置快照以归因协议 2 隔离旧口径成绩。P3 持久模拟已将主/备用尝试随动作或故障保存，报告从 SQLite 汇总，旧数据缺字段显示未采集；真实模型/服务版本、usage 和服务分段耗时仍待补。单一总预算不要求不同层默认值机械相同：RPC 还需留回退和通信时间；按阶段配置预算须有测量依据，不能由异常长尾倒推模型计算量。

新实现须同步 [评测方案](../ai/evaluation-plan.md) 的字段和命令，不先宣称能力完成。默认实验使用受控预算；压力测试显式命名并分表，不靠放大超时掩盖故障。

## M1 · 冻结数据与基线，再调参

| ID | 任务 | 验收 |
| --- | --- | --- |
| A1.1 | 审核原 35 例及新增场景事实与裁判，优先收紧 K 保护、叉子保留等意图/条件不一致样本；区分规则必须与战术期望 | 每条期望说明依据，允许合理替代动作；守恒、历史与隔离通过；改裁判升级套件重跑，不覆盖旧成绩 |
| A1.2 | 以 55 例公开开发集及覆盖/对称回归为基础，建验证、最终保留集；覆盖叫分档、庄闲、四座位、100 分明牌及首手/跟牌/残局；冻结种子清单和协议 | 集合指纹与互斥检查齐全；保留集确认前不用于调参；公开题通过率与泛化证据分栏 |
| A1.3 | 重跑三种离线配置和真实 Laya/Qwen；模型先并发 1，以 none/low × bidAdvice 开/关做受控消融，开发诊断每组合至少 3 个独立 run | 全部 run、波动、阶段成绩、原生覆盖、回退、P50/P95 与超时均报告；同服务版本、输入、提示词、格式、重试及预算；先服务冒烟再扩量 |

三个 run 是发现波动的起点，不是显著性保证；单次小场景集不报告稳定 P99。思考档位对照交错运行减少时段差异，产品预算实验另成表。Laya 扣底启发式独立归因；部署别名不能代替真实权重版本。

## M2 · 每轮只回答一个策略问题

| ID | 方向与首批假设 | 验收 |
| --- | --- | --- |
| A2.1 | 共用叫分/定主/扣底：检查 `smart.ts` 的过高叫分、长套与分牌混淆、副牌 K 保护；起叫和竞争再叫分开诊断，出牌引擎固定 | 修 bug 先复现；阶段替换和完整对战记录合同分布、成约率、实际赢副，不只把动作改成 35 题答案 |
| A2.2 | 搜索校准：在可完整求解的小残局比较 DDS 与续打估计；分别消融节点预算、世界数、rollout、战术先验 | 同观察/采样世界的逐候选误差与排序、精确/截断比例、耗时；再经普通视角独立对战确认收益 |
| A2.3 | 模型提示词与配置：处理 Prompt 2.0 的 4 类反向变化和动作/解释不一致；根据 M1 选档位，再考虑新模型或示例 | 请求/响应、原生合法率、回退及阶段变化齐全；示例与验证/保留集互斥；服务故障与策略失误分开 |

DDS 的完整信息解只对给定世界、求解目标和规模成立，是残局校准工具，不是普通视角策略的普适最优动作或整局“上界达成率”。暗牌答案可用于离线裁判，但暗牌不能回灌 Actor 输入。

多引擎投票和未经对照的增大搜索预算后置。P2 的多模型配置选择按当前主线交付，新模型的牌力结论仍需对照。每轮保存“质量—延迟—调用量”对照、改善与退化，选择下一项最有证据的变量。

## M3 · 用整副牌确认候选

| ID | 任务 | 验收 |
| --- | --- | --- |
| A3.1 | 扩展现有 `match-battle.ts`，接入普通视角 LLM、阶段组合配置、总预算与实际回退链；分开模型原生结果和含回退系统 | 四阶段无暗牌/seed；100 分成功扣底后同步明牌；全 Pass、强制合同、超时、取消和回退均有日志；故障不静默删组来抬高成绩 |
| A3.2 | 扩大换边实战，补座位/发牌者覆盖和合同分层；冒烟后按预声明样本量/预算完成独立确认批次 | 以 `winnerSide` 算赢副，发牌组为统计单位；报告差值、95% 区间、有效组数、干预/故障、庄闲分布；动作可重放 |
| A3.3 | 候选放行与退回；牌力、离线、可靠性和延迟分别判断 | 固定对手、数据、资源预算；原生模型证据不足时只评价含回退系统；实验可保留，默认替换需独立确认 |

十组对战用于回归冒烟。离线候选可先以 100 个独立组诊断，再按目标效果、区间宽度和预算确定确认规模；模型先估算请求量。现有 Hoeffding 区间在 100 组仍很宽，不承诺固定局数足以排序。反复试探后不能挑某次区间不含 0 的报告宣称胜出。

**默认替换门槛**：规则和信息隔离全过；独立确认集上，相对当前实际默认配置的赢副率差 95% 区间下界大于 0；最终动作合法、完成/回退表现达标；目标环境端到端 P95 不超过实验前声明的预算。记录实际默认配置，不能把 CLI 的 `bridge-deep` 自动当作产品默认。提速或离线替换另立等效/非劣协议，不宣称牌力提高。

先对比基线和少量候选，全量 round-robin/Elo 后置。Elo 展示多对手趋势，不能替代配对区间；已有阶段报告也不能替代整副牌确认。

## M4 · 基于证据决定是否训练

| ID | 任务 | 前置与验收 |
| --- | --- | --- |
| A4.1 | 将已有轨迹整理为持久语料：可见观察、合法候选、实际动作、终局、来源、搜索质量与版本 | M0–M3 契约稳定；按整副牌划分、去重；Mock、失败、未评估和低质量标签排除或单列；Actor 输入与全局裁判状态分开 |
| A4.2 | 先做受控监督/蒸馏；Laya 是否可训取决于工具支持，必要时使用独立策略原型 | 教师已通过实战确认；先限定出牌阶段，其他阶段冻结；合法掩码、特征投影、推理耗时和普通视角评测齐全 |
| A4.3 | 蒸馏不足且算力明确后，再做自博弈 RL / 历史策略池 | 基础奖励先用团队终局胜负；密集吃分/成约奖励单独消融，验证不会鼓励虚高叫分；非对称 Critic 的全局信息不进入 Actor 或推理 |
| A4.4 | 导出模型接入 `DecisionEngine`，逐步扩训练阶段与部署 | 模型/特征/规则版本可追溯；非法与异常回退守护；经 M3 同协议验收再决定上线和默认替换 |

已有日志可支撑调试与重放，缺的是来源清楚、质量筛选和集合互斥的训练集。不预设 RL 必然超过搜索，不把研究方案写成已在训练。
