# UI 与游戏交互审查（2026-10-15）

本轮检查普通对局、Debug、AI 观战、设置、规则、历史、皮肤选择及手机横屏操作。保留四家独立引擎配置、初始暂停、侧栏信息常驻与正方形桌面牌桌。

## 已复现并修复的问题

| 问题 | 原因与修复 | 回归证据 |
| --- | --- | --- |
| 查看规则、设置、历史等弹窗时自动对局仍在运行 | 弹窗原来只处理焦点；通过统一对局上下文暂停展示和决策，关闭后等待手动开始 | `ui-modal-gameplay.test.ts`：六类入口；浏览器检查规则打开与关闭 |
| 侧边弹窗打开后仍能点击牌桌或顶栏 | 焦点循环没有隔离鼠标和触屏；统一隔离背景输入，多层弹窗按计数恢复原状态，切换 Debug 后仍隔离，方向提示不被禁用 | `ui-accessibility.test.ts`、`ui-modal-gameplay.test.ts` 与浏览器输入边界检查 |
| 观战分数及行动者比牌桌动画提前变化 | 侧栏读最终牌局，牌桌读当前展示步骤；统一使用当前步骤的牌局与行动座位 | `ui-app-interaction.test.ts`：收墩期间仍显示计分前分数 |
| 动画下一步与空格推进后继续自动连播 | 普通和 Debug 展示入口直接推进队列；改为先暂停再推进，与单步操作一致 | `ui-app-interaction.test.ts`：鼠标和空格均先暂停 |
| 开始／暂停清空人工选牌 | 决策失效清理同时清除了 UI 选择；只切换运行节奏时保留同局面选择，换局面或配置仍清除 | `action-presentation.test.ts`：出牌与扣底两个阶段 |
| 手机皮肤面板嵌在顶栏，且确认按钮被裁剪 | 自定义面板位于顶栏滚动容器；统一挂载到停靠区，头部关闭和底部确认固定，选项独立滚动 | `interaction-review.test.ts`：实测不相交、两按钮可见、关闭后焦点和原牌桌位置恢复 |
| 触屏动画按钮仅 24px，宽屏触屏叠牌使点击区相交 | 鼠标布局被触屏沿用；触屏按钮至少 44px，手牌使用完整独立牌位，鼠标仍保持一行布局 | `interaction-review.test.ts`、`desktop-dashboard.test.ts`：实测尺寸与矩形相交 |
| 普通牌桌信息排列松散，叫分与动作展示占用手牌区域 | 桌面沿用 Debug 的桌沿朝向，南家信息居中；各阶段操作及动作说明集中在右侧，手机横屏保留侧栏 | `desktop-dashboard.test.ts`、`mobile-layout.test.ts`：普通、Debug、观战、70/100 分扣底及弹窗检查 |
| 观战音效和退出按钮横贯整个侧栏 | 改为图标与文字组成的紧凑工具行，直接显示音效状态，窄屏自动换行 | `spectator-toolbar.test.ts`：三种尺寸、独立点击区域、44px 高度及实际操作 |

## 验证范围

- 桌面 1920×1080、1280×720，以及手机横屏 844×390；分别覆盖鼠标与触屏。
- 叫分、定主、扣底、出牌、观战动画、结算与本副复盘沿用已有真实交互回归。
- 弹窗的关闭、Escape、焦点返回、多层输入恢复，以及失败保存与历史读写路径。
- AI 观察对象、规则计分和决策算法未修改；本轮修复集中在 UI 与对局交互编排。

长期约束见 [UI 布局与交互规范](interaction-guidelines.md)。本次 UI 提交内容已在独立快照验证：`pnpm test` 75 个文件、891 项通过；`pnpm test:browser` 58 项通过；`pnpm build` 类型检查与生产构建通过。新增交互回归均先确认目标失败，再实现修复；纯样式调整使用真实浏览器几何检查。
