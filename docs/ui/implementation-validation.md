# 正式 UI 接入与验证

日期：2026-10-14。设计依据见[UI 与交互方案](../game-ui-interaction-design.md)和[游戏产品设计](../game-product-design.md)。本记录描述正式 React 游戏入口；[独立 HTML 原型](interaction-prototype.html)继续用于设计评审。

## 已接入的范围

- 经典皮肤使用青绿桌面、米白牌面与金色主操作；普通桌面右侧增加“本副战况”，分别展示庄家 / 闲家的吃分、锁定线、差额及未打出分。85 分局目标为 85 / 20，100 分局为 100 / 5；叫分尚未结束时不显示未成立的合同进度。
- 页头、桌上信息与手牌操作分层：行动者、主牌和合同常驻；叫分 / 定主 / 扣底操作靠近手牌，16 张扣底手牌有足够空间。定主的“张数最多”只是统计提示。
- 出牌主按钮直接写出选中牌，例如“出牌 A♥”。有同门时说明须跟的花色，缺门时说明可以出任意牌；继续使用现有出牌确认偏好。Debug 强制确认。
- 普通牌桌在 100 分成功扣底后显示庄家搭档的规则明牌；修正北家明牌的网格列与紧凑布局。上一轮留牌、收分标签和下一轮提示保留，并为标签留出间距。
- 页头增加 Debug 入口，复用现有模式切换。工作台保留单步、自动、暂停、建议、撤销、引擎配置、历史和沙盒；增加临时看牌信息提示、五页键盘导航及语义关联。
- Debug 非法跟牌、分牌扣底显示禁用原因，点击不会选择或提交；修正叠牌遮挡导致点中相邻牌和选中牌遮挡确认按钮的问题。
- 候选没有真实评估时显示“未评估”，不填充 50% 条形；真实 0% 按零显示。尚无决策记录时不宣称“正常无降级”。

本批复用原来的规则、会话、观察投影、历史与结算组件，未更换引擎或新增依赖。单副练习、新教学、结算直接定位复盘以及真实玩家任务观察仍属于后续产品切片。

## 实机截图与布局边界

[普通牌桌 · 选牌确认](game-table-desktop.jpg) · [Debug 工作台](game-debug-workbench.jpg)。截图来自正式 Vite 入口的人工操作，不使用原型中的固定诊断数据。

普通桌面在 1280 × 720 检查了叫分、定主、16 张扣底、100 分规则明牌、选牌 / 确认和上一轮留牌。390 × 844 的手机检查沿用现有横屏适配，空间不足时滚动访问手牌与工具。不会将手机横屏容器当作新的竖屏玩法。

Debug 保持四座朝向和 1:1 方桌，最小边长为 640 CSS px；低高度或窄屏允许滚动查看方桌与诊断。为保证密集牌桌每张牌的中心可点，叠牌露出比例调整为 55%；不能将这一几何检查等同于触屏可用性研究。

浏览器回归夹具位于 `tests/fixtures/debug-hit-layout.html`，开发服务可访问 `/tests/fixtures/debug-hit-layout.html`。它使用真实 `SquareTable`，隔离 AI、网络与存档，在四个行动座位分别检查 `elementFromPoint` 是否命中每张牌：1280 × 720 下四座均为 48 / 48。正式 Debug 中另完成一轮南 → 西 → 北 → 东的人工选牌和确认，并检查收牌后进入下一轮。

## 测试先行与最终检查

行为改动先在 `tests/ui-app-interaction.test.ts`、`tests/ui-phase-actions.test.ts` 与 `tests/table-seat-presentation.test.ts` 写预期，再运行确认目标失败：缺少战况与 Debug 入口 / 页签、确认按钮没有选中牌名、非法 Debug 牌仍可选择、无评估时填充假的胜率及 0% 未按零展示。随后完成对应最小实现并确认通过。纯布局与配色调整没有制造行为失败测试。

最终 `pnpm test` 为 **67 个文件、807 项通过**；`pnpm build` 类型检查和生产构建通过。构建保留已有的单包超过 500 kB 提示，未在本次 UI 任务中进行依赖拆包。实际游戏浏览器控制台未发现错误。

全量回归包括原有信息隔离、100 分扣底前后公开与持续同步、历史保存失败、上一轮和复盘路径。工程测试与上述人工操作只证明相应路径通过，不声称新手完成率、触屏误点率或 AI 牌力有所提升。
